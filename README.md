약을 짓고, 글을 짓고, AI와 함께 만듭니다.

- 주소: https://susanaa0702.github.io/susanna-archive/
- 정적 HTML만 씁니다. 빌드 도구·프레임워크·외부 라이브러리 없음 (구글폰트 링크만 예외).
- 모든 페이지에 `noindex, nofollow` — 검색에는 잡히지 않지만, **주소를 아는 사람은 읽을 수 있습니다.**

### 모든 페이지가 지켜야 할 것

- `<html lang="ko">`, 모바일 뷰포트 메타 필수
- `<head>`에 `<meta name="robots" content="noindex, nofollow">` — **새 페이지에도 빠짐없이**
- 색은 전부 `:root` CSS 변수로. 색을 바꿀 땐 변수 한 곳만 고칩니다
- 외부 CSS·JS 라이브러리 금지. 스타일은 각 파일 안에 인라인 (구글폰트 링크만 예외)
- 파비콘은 **상대경로** — 루트는 `favicon-32.png`, 하위 폴더는 `../favicon-32.png`
  (GitHub Pages 프로젝트 사이트는 `/susanna-archive/` 아래로 서빙되므로 `/favicon-32.png`처럼 루트 절대경로를 쓰면 아이콘이 깨집니다)
- 외부 사이트로 나가는 링크만 `target="_blank" rel="noopener noreferrer"`. 아카이브 안에서 도는 링크는 같은 탭
- 푸터 문구는 모든 페이지에 동일: `글짓는 약사 수산나 · 디퍼 언브랜딩 살롱 아카이브`

## 콘텐츠를 쌓는 규칙

### 파일 이름

**`YYMMDD.html`**로 통일합니다. 날짜순으로 자연히 정렬되고, 새 글은 같은 규칙으로 떨어뜨리면 목록에 한 줄씩 쌓입니다.
같은 날 여러 개면 `YYMMDD-키워드.html`. 과제는 `YYMMDD-이름.html`, 독서는 `YYMMDD-책이름.html`.

### 인사이트 리포트는 "결과물 먼저, 성찰 나중"

- **먼저**: 그 주에 실제로 만든 것을 눌러볼 수 있게 보여줍니다. 링크·이미지·카드,
  그리고 **어떻게 만들었는지(쓴 프롬프트·방법)를 같이 공유**합니다. 이게 리포트의 중심입니다.
- **나중에**: 성찰은 하단에 **짧은 항목(제목 + 한두 줄)** 요약으로. 긴 문단으로 풀지 않습니다.

### 성찰은 내 것만 쓴다

- 내가 실제로 겪고 느낀 것만 성찰에 넣습니다. AI가 조사·판단한 내용은 성찰이 아닙니다.
- 내가 쓰지 않는 단어를 얹지 않습니다. 그럴듯한 요약보다 실제로 한 일을 그대로.
- AI(에이전트)가 어떻게 판단하고 일했는지는 **별도 섹션에 그 목소리로** 싣습니다.
  살롱에서 이 꼭지가 특히 도움이 된다는 반응이 있었습니다.
- 비유보다 직접적인 표현을 씁니다.

### 공개 저장소라는 걸 잊지 않는다

- 병력·가족·실명·사연 같은 사적인 내용은 공개본에 싣지 않습니다.
  과제가 개인의 몸이나 건강을 다룰 땐 **내 응답·증상은 빼고 일반 자료로만** 정리합니다.
- 원본(사적인 대목이 든 정본)은 로컬 볼트나 비공개 저장소에만 둡니다.
  공개본은 그 **사본**이고, 고칠 일이 생기면 **정본을 먼저 고치고 다시 옮깁니다.**
- 공개본에 다른 사람과의 관계나 거리를 적지 않습니다 — 당사자가 읽습니다.

### 약사의 자리 — 사례는 싣지 않는다

이 갈래는 두 가지 글로 채웁니다. 카드의 태그로 구분합니다.

| 태그 | CSS 클래스 | 무엇 |
|---|---|---|
| 일반 자료 | `tag-data` | 카운터에서 자주 받는 물음에 대한 일반적인 정보 |
| 상담 | `tag-seat` | 상담이라는 일 자체에 대한 글 — 사람이 아니라 태도와 방식 |

지켜야 할 것:

- **상담에서 들은 증상·복용약·사연은 어떤 형태로도 싣지 않습니다.** 나이·성별·복용약 몇 가지만 겹쳐도 당사자는 자기 이야기인 것을 압니다. "어떤 분이" "한 손님이" 같은 익명 처리도 하지 않습니다.
- 일반 자료는 특정한 누구가 아니라 **여러 번 반복해 들은 물음**의 형태로 씁니다.
- 모든 글 하단에 면책 문구를 둡니다 — 일반적인 정보이며 개별 상담·진료를 대신하지 않는다는 것. 틀(`counsel/template.html`)에 이미 들어 있습니다.
- 참고한 자료는 출처를 적습니다.
- '상담' 태그 글은 수산나님의 방식에 대한 글이므로, 성찰과 같은 규칙을 따릅니다 — 실제로 겪은 것만, 쓰지 않는 단어를 얹지 않기.

### 독서 기록 — 남의 말은 옮기지 않는다

이 갈래도 태그 둘로 나눕니다.

| 태그 | CSS 클래스 | 무엇 |
|---|---|---|
| 독서모임 | `tag-club` | 모임에서 함께 읽은 책 |
| 혼자 읽기 | `tag-solo` | 혼자 읽은 책 |

지켜야 할 것:

- **모임에서 다른 분들이 한 이야기는 옮기지 않습니다.** 당사자가 읽습니다. 내가 읽고 생각한 것만 씁니다.
- 인용은 짧게 하고 쪽수와 판본을 적습니다. 긴 대목을 통째로 옮기지 않습니다 — 저작권이 있습니다.
- 책 소개나 남의 해설을 옮기지 않습니다. 안 읽고 쓴 글은 티가 납니다.
- 판본이 다르면 쪽수가 어긋납니다. 어느 판본으로 읽었는지 적어둡니다.

## 새 인사이트 한 편 추가하는 법

1. `insight/template.html`을 복사해 `insight/260905.html`처럼 그 주 날짜로 저장합니다.
2. 파일을 열어 맨 위 안내 상자를 지우고, 날짜·제목·한 줄 요약을 고칩니다.
3. **만든 것 → 어떻게 만들었나(프롬프트) → 배운 것 → 에이전트의 기록** 순서로 채웁니다. 이미지는 `assets/`에 넣고 `../assets/파일명`으로 겁니다.
4. `insight/index.html`을 열어 목록 맨 위에 `<li>` 한 줄을 추가합니다 (주석으로 예시가 들어 있습니다).
5. `git add -A && git commit -m "..." && git push` — 1~2분 뒤 자동 배포됩니다.

같은 방법으로 `assignment/` · `counsel/` · `reading/`에도 각 폴더의 `template.html`을 복사해 씁니다.

## 배포

`main`에 push하면 GitHub Actions(`.github/workflows/deploy.yml`)가 자동으로 배포합니다.

```bash
git add -A && git commit -m "새 인사이트 추가" && git push
```

설정은 **Settings → Pages → Source: GitHub Actions** 입니다.

워크플로 파일을 로컬에서 push하려면 깃허브 토큰에 `workflow` 권한이 있어야 합니다. 이 컴퓨터의 토큰에는 없어서 (`gist, read:org, repo`) push가 거절됩니다:

```
! [remote rejected] main -> main (refusing to allow an OAuth App to create or
  update workflow `.github/workflows/deploy.yml` without `workflow` scope)
```

그래서 2026-08-29에 이 파일은 **깃허브 웹에서 직접 만들었습니다** (Add file → Create new file). 웹 편집기는 이 제한을 받지 않습니다. 앞으로 이 파일을 고칠 때도 같은 방법을 쓰거나, 별도 터미널에서 아래를 실행해 권한을 더하면 됩니다 (브라우저 승인까지 마쳐야 반영됩니다):

```bash
gh auth refresh -h github.com -s workflow
```

**워크플로 파일이 아닌 보통 페이지는 이 제한과 무관합니다** — 새 인사이트·과제·독서 기록은 그냥 `git push`로 올리면 됩니다.
