어떻게 만들었나

Claude Code(사막여우)에게 요청서 한 장을 건넸습니다. 코드는 한 줄도 직접 쓰지 않았습니다. 순서는 이랬습니다.

  1. 요청서를 준다 — 만들기 전에 나에게 먼저 물어보라고 적어서
  2. 네 묶음(정체 · 색과 글꼴 · 담을 것 · 공개 범위)을 순서대로 묻고 답한다
  3. 답을 정리해 확인서로 보여주면, 확인하고 짓기 시작한다
  4. 브라우저로 열어 링크·모바일 화면을 확인한다
  5. 깃허브에 올리고 배포를 켠다

쓴 프롬프트

이게 이 리포트의 중심입니다. 실제로 건넨 요청서를 뼈대만 남기고 줄였습니다. 그대로 복사해 쓰셔도 됩니다.

너는 나의 개인 아카이브 사이트를 짓는 개발·디자인 파트너야. 나는 디퍼 언브랜딩 살롱의 연구원이고, 살롱에서 쌓은 인사이트(주간 성찰), 과제 결과물을 한자리에 모아두는 공개 웹 아카이브를 만들고 싶어. 정적 HTML만 쓰고(빌드 도구·프레임워크 없이), GitHub Pages로 배포한다. 아래 순서대로 진행해줘. ── 1단계 — 먼저 나에게 물어봐 (만들기 전에) 한 번에 다 묻지 말고, 아래 묶음을 순서대로 물어보고 내 답을 받은 뒤 다음으로 넘어가. 내가 "모르겠다"고 하면 네가 두세 가지 안을 제시하고 고르게 해줘. (1) 정체 — 이름/닉네임, 한 줄 소개(태그라인), 브랜드나 스튜디오 이름 (2) 색과 글꼴 — 이미 정한 브랜드 색이 있나? 없으면 내가 좋아하는 것 (계절·시간대·풍경·사물)을 물어보고 거기서 5색 팔레트를 제안해줘 — 배경 / 강조 / 보조 / 포인트 / 본문글자. · 배경은 흰색보다 살짝 물든 색을 권한다. · 본문 글자와 배경의 명도 대비는 4.5:1 이상. 계산해서 확인하고 알려줘. · 밝은 노랑·연한 파스텔은 선·아이콘 전용으로 두고 글자색으로 쓰지 마. · 글꼴은 구글폰트에서 한글 3종 — 제목용 / 본문용 / 캡션용. (3) 담을 것 — 랜딩에 둘 큰 갈래는 둘이다: 인사이트 · 과제. 각 갈래를 뭐라고 부를까? 이미 만들어 둔 결과물이 있으면 주소를 알려줘. (4) 공개 범위 — 검색엔진에 노출할까, 링크를 아는 사람만 들어오게 할까? (권장: 노출하지 않음) 깃허브 계정 이름과 저장소 이름. 답을 다 받으면 정리해서 보여주고 내 확인을 받은 뒤 만들기 시작해. ── 2단계 — 이 구조로 만들어줘 저장소루트/ ├─ index.html 랜딩 — 두 갈래 카드 ├─ insight/index.html 인사이트 목록 (세로 리스트, 최신이 위) ├─ insight/YYMMDD.html 리포트 한 편 ├─ assignment/index.html 과제 목록 (카드 그리드) ├─ assets/ · favicon-32.png · favicon-180.png └─ README.md 랜딩은 화면 한가운데 세로 정렬, 스크롤 없이 한눈에. 갈래마다 강조색을 다르게 줘서 눈으로 구분되게. 아직 채워지지 않은 칸은 점선 자리표시로 남겨둬 — 자라는 아카이브라는 게 보이게. 공통 규격: html lang="ko", 뷰포트 메타 필수. 색은 전부 :root의 CSS 변수로. 외부 CSS·JS 라이브러리 금지(구글폰트 링크만 예외). 파비콘은 상대경로. 외부 링크만 target="_blank" rel="noopener noreferrer". 검색 노출을 원하지 않으면 모든 head에 noindex, nofollow. ── 3단계 — 콘텐츠를 쌓는 규칙 (README에 적어둘 것) 파일명은 YYMMDD.html로 통일한다. 인사이트 리포트는 "결과물 먼저, 성찰 나중"으로 쓴다. · 먼저: 그 주에 실제로 만든 것을 눌러볼 수 있게. 어떻게 만들었는지 (쓴 프롬프트·방법)를 같이 공유한다. 이게 리포트의 중심이다. · 나중에: 성찰은 하단에 짧은 항목(제목 + 한두 줄) 요약으로. 성찰은 내 것만 쓴다. · 내가 실제로 겪고 느낀 것만. AI가 조사·판단한 내용은 성찰이 아니다. · 내가 쓰지 않는 단어를 얹지 않는다. · AI가 어떻게 판단하고 일했는지는 별도 섹션에 그 목소리로 싣는다. · 비유보다 직접적인 표현을 쓴다. 공개 저장소라는 걸 잊지 않는다. · 병력·가족·실명·사연 같은 사적인 내용은 공개본에 싣지 않는다. · 원본은 로컬이나 비공개 저장소에만. 공개본은 사본이고, 고칠 일이 생기면 정본을 먼저 고치고 다시 옮긴다. 새 페이지를 더한 뒤엔 세 곳을 같이 고친다 — 목록 index.html, README, 커밋. ── 4단계 — 배포 main에 푸시하면 GitHub Pages로 자동 배포되게 해줘. ── 5단계 — 만든 뒤 1. 브라우저로 열어 랜딩 → 목록 → 상세로 눌러 들어가 링크가 살아 있는지 확인. 2. 폭 375px(모바일)에서도 무너지지 않는지 확인. 3. "새 인사이트 한 편 추가하는 법"을 다섯 줄 이내로 정리해줘.

실제로 건넨 요청서. 길이가 있어 상자 안에서 스크롤됩니다.

배운 것

  • 색 고를 때 옆에 나란히 걸어보니 바로 알겠더라.
  • 배포가 막혀 돌아갔을 때 당황했지만 사막여우가 잘 알아서 해 주리라 믿었다.

에이전트의 기록

사막여우 (Claude Code)

요청서에 "구글폰트에서 한글 3종"이라고 적혀 있었는데, 제가 본문용으로 제안한 Pretendard는 구글폰트에 없습니다. 외부 CDN을 써야 하고 그러면 "외부 라이브러리 금지" 규칙과 부딪힙니다. 제 실수였고, 곧바로 알리고 구글폰트의 Noto Sans KR로 바꿨습니다. 다만 폰트 스택 맨 앞에 Pretendard를 남겨서, 그게 설치된 컴퓨터에서는 그 글꼴로 보이게 했습니다.

색은 눈으로 고르지 않고 계산했습니다. 다섯 색 각각을 배경 #F6F4EC에 대고 WCAG 명도 대비를 재서, 본문 글자는 13.05:1, 강조 6.80:1, 보조 5.71:1로 기준(4.5:1)을 넘겼습니다. 포인트색만 3.36:1로 못 미쳤습니다. 그래서 그 색은 선과 아이콘에만 쓰고, 짧은 글자가 필요한 자리를 위해 짙은 짝(#A85B2C, 4.54:1)을 따로 만들어 변수에 넣었습니다.

배포는 처음 계획대로 되지 않았습니다. 깃허브에 자동배포 파일을 올리려면 토큰에 workflow 권한이 있어야 하는데 이 컴퓨터의 토큰에는 없었습니다. 권한을 더하려면 터미널에서 로그인을 다시 해야 하는데 PowerShell이 관리자 창으로만 열려 그 길도 막혔습니다. 그래서 방식을 바꿨습니다 — 자동배포 파일 없이, 깃허브 웹 화면에서 브랜치 배포를 켜는 방법입니다. 결과는 같습니다. 파일을 올릴 때마다 사이트가 다시 만들어집니다.

여기서 한 번 더 걸린 것이 있습니다. 이미 만들어둔 커밋 안에 그 파일이 들어 있어서, 나중에 지우는 커밋을 얹어도 깃허브는 계속 거절했습니다. 올라가는 모든 커밋을 검사하기 때문입니다. 그래서 그 파일이 처음부터 없었던 것처럼 커밋을 다시 만들어 올렸습니다.

요청서에 없던 파일 두 개를 더했습니다. 목록의 점선 자리표시가 눌러도 아무데도 가지 않으면 확인이 안 되고, 다음에 글을 더할 때 복사할 원본이 필요해서 각 폴더에 template.html을 두었습니다. 틀 안의 이미지 자리가 깨져 보이지 않도록 assets/example.png도 만들었습니다.

마지막으로 배포된 주소에 직접 들어가 다섯 페이지의 링크 스물여섯 개를 눌러 전부 살아 있는 것을 확인했고, 폭 375px에서 가로로 넘치는 곳이 없는지도 확인했습니다.
